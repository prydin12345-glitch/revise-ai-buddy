# Profile Builder: evidence provenance and rejection details

Baseline: main `d267ffe8` (merged #50). Verification date: 7 November 2026. The reported 18:05/18:06 failures were described by Lovable; the exact live model responses and private uploaded file are not available in this checkout. Regression fixtures reproduce the reported shapes and use separately reviewed official sources, rather than claiming to replay those private responses.

## What was wrong

The source validator required a literal uploaded-PDF statement for every known fact, including a known course's untiered classification. It also treated a topic fact tagged `observed` as unsupported even when an active specification stated it directly. Full mocks then required compulsory-question instructions that a specification may omit. Those rules are on the question-paper cover, so silently assuming that all questions are compulsory would be unsafe.

The review also found two specific parsing/validation defects: `2 hours` followed by `85 marks` could be parsed as 205 minutes, and the legitimate AQA phrase “short and long answer questions” did not satisfy the long-response format check. Calculator evidence previously accepted a generic keyword from a maths-skills passage. The first rejected extraction reason was stored, but the second was replaced by a general verification message.

## The resulting behaviour

- Exact reviewed untiered course identities now receive typed `catalogueFacts` provenance, independently re-resolved during validation. No PDF quote is invented. Model output cannot nominate this authority; explicit Foundation/Higher contradictions are rejected. Unknown courses retain their evidence requirements.
- Direct facts from active specifications/institution briefs may use an `observed` reference only when the actual quote supports the value. Observed patterns from samples/past papers do not automatically become mandatory future rules. Old evidence has no new default fields or mutations, preserving its canonical fingerprints.
- The exact reviewed AQA A-level Physics `7408/1` identity can use real Paper 1 cover instructions for calculator use and compulsory selection. They have their own official URL, checksum, physical page and review record. This fills source-unknown rules, preserves explicit contrary uploaded values as conflicts, and grants no gold badge or approved paper contract. It does not apply to Paper 3, AS, GCSE, another course or an incompatible explicit issue.
- Uploaded IDs, checksums, owner authority, URLs and literal locations are checked before server provenance is added. An uploaded/model response cannot replace a reviewed document or supply catalogue authority. Legacy upload ingestion applies the same boundary.
- Calculator permission requires an explicit instruction or literal materials context; a maths example or model-assigned section name is insufficient. Prohibition context defeats a cherry-picked positive word. Duration minute components require a minute unit, so following mark totals are not consumed as time.
- Index v4 retrieves bounded adjacent literal continuation lines for wrapped rules, stopping at paragraph, topic, component and qualification boundaries. Existing page/byte/chunk limits remain. Quote validation still requires the supplied words; an incomplete prefix cannot establish a missing sentence ending.
- Every rejected extraction/draft attempt has a bounded private diagnostic record. The public owner view exposes only controlled code/field/message summaries, never private rejection detail, invalid model objects or provider errors. Failed checks remain within the original three-call budget; status checks do not replay a call.
- The UI shows the reason for each failed check and moves focus/scroll to it after processing settles. A collapsed “Verified assessment facts” section distinguishes course-catalogue tiering from reviewed official instructions.

The source cache includes index/provenance policy versions, catalogue proof and reviewed rule-pack identity/checksums. Previously completed proposals are not rewritten. Shared ownership, release protection, marking/mastery, profile snapshots, quotas and generation budgets remain authoritative. No schema migration, generated Supabase-type edit or live data update is needed.
