# Custom exam profile editor

Manually created profiles now use the same plain header, counts, flat topic rows and icon controls as the AI editor. Existing profiles open on Topics. New profiles collect their required basics before opening the workspace. Exam settings and Paper layout hold the existing qualification/course/tier, question, timing, advanced and section controls. Studied content remains available for applicable subjects. The AI builder is still an explicit action, including during initial setup.

The Topics pane shows the saved selection in its original order, including entries absent from the current dictionary or library. Search, original/A–Z sorting, library browsing and tab navigation are views over that draft. They do not rebuild the selected topics or save anything. Existing duplicate and case-variant rows are retained; ambiguous duplicate renames are disabled. Add accepts comma/newline lists and skips new duplicates. Removing from a profile does not delete its library entries or old results. Undo restores topics and their display labels while retaining unrelated edits.

Display-name changes use optional `paper_blueprint.topicEdits` in the existing JSON column. Canonical topic strings remain unchanged in quiz/exam selections, performance keys and navigation. Profile details, exam creation and practice creation read the display names from the complete saved profile. Existing AI templates keep their current validation and editor route. No manual notes or source-evidence claims are added.

The lossless save helper compares the opening UI payload with current values and carries through unchanged raw fields. Nulls, explicit zeroes, custom qualifications, unknown tiers, calculator policies, question counts, timing, studied content and unrepresented nested paper metadata survive unrelated changes. Exact layouts retain section/question order, purposes, marks, optional answer counts and extra metadata. Existing guided/versioned contracts stay on their saved revision until explicitly reapplied; explicit course/paper changes clean the applicable old contract fields without inventing assessment details.

Save awaits an explicit outcome from the real hook. Failures keep the draft open. If creating the core row succeeds but its assessment tier fails, retry updates the created ID instead of inserting again. The real parent callback has separate coverage for that retry. Missing/failed tier writes do not claim complete success. Discard restores the opening draft; closing or switching to the AI builder with edits requires an explicit discard. Nested dialog dismissal is sequenced to release its focus and pointer locks.

Verification also covers layouts above 20 questions, pending studied-text input across editing sessions, raw legacy topic strings, aliases with unknown metadata, unsupported legacy references and supported-course choice safeguards. Full results and practical limits are in `verification.json`; the browser harness uses production components and save code with synthetic, owner-scoped in-memory storage. It does not establish live database/RLS behavior or physical iOS/Safari compatibility.

There are no dependency, lockfile, environment, database or Edge function changes. `edge-function-dependencies.json` records the actual transitive import inspection of all Edge entry points. The frontend-only Lovable handoff is in `lovable-prompt.md`. Nothing is deployed or published by this task.
