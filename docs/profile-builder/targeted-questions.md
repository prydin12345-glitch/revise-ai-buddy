# Profile Builder: combined specifications and targeted questions

Baseline: `e61a9a19d9fbe2a4b9b2a90a930991c5dccbcda6`, reviewed 7 November 2026. This implements the [saved brief](codex-combined-spec-and-targeted-questions.md), preserving the merged evidence-provenance fix and Lovable's subsequent source filtering, quota wording and drafting-time changes.

## Causes and resulting behaviour

Combined specifications need qualification and course boundaries before assessment names can be compared. The reader now uses literal AS/A-level headings, exact course-code headings and explicitly coded assessment rows across subjects and boards. Other courses' rows are out of scope. Exact heading associations also support non-slash component codes and GCSE combined/separate science. Neither a selected course nor a student's page choice gives meaning to an unlabelled table column.

The reported ambiguity was also reproduced with the real parser on the **complete 94-page Physics and 96-page Chemistry specifications**. Later weighting tables contained rows such as `Paper 1 Paper 2` and `Paper 1 85 x1 85`. Discovery incorrectly treated those tails as alternative paper titles. Those table shapes are now excluded from assessment choices. Each complete document yields exactly Paper 1/2/3 without ambiguity; all six scoped indexes remain bounded literal excerpts. [Recorded metrics](targeted-questions/official-index-results.json) contain no official PDF text.

When the source cannot settle a choice, the authenticated API returns `missingItems`: a field, a plain-language question and server-owned choices when known. The screen shows the current question only, with the other choices in a read-only summary and a **Change** link. Course variants remain explicit. Clicking Change and returning to the question keeps the same job; actual identity/source edits require a fresh check. Attached files remain until explicitly removed or replaced.

`answer_source` submits one allowlisted answer with the owned job ID and expected revision. Assessment and option choices refine retrieval intent; they cannot establish marks, timing, tier, calculator permission, topics or compulsory-question rules. Answers resume deterministic indexing of retained parsed text without parsing the PDF again. A selected physical page can exclude an irrelevant comparison elsewhere only when its original source spans have a trustworthy course/qualification anchor. Truly inseparable tables request the relevant assessment overview rather than guessing. Text assessment fallback requires a literal heading in assessment context, not an arbitrary substring.

If extraction already produced valid partial evidence, a page answer preserves it, the cursor, original receipt, quota reservation, call count and active processing time. Further extraction is needed only when source facts remain unresolved. Original intake hashes remain immutable; explicit selection refinements cannot contaminate another component's cache identity. Status checks and repeated/stale answers do not issue provider calls. Acquired stale leases are released normally, and confirmation rechecks the current identity, mode and revision.

## Storage, limits and safeguards

No migration or generated-type edit is needed. New recoverable questions are a guarded substate of the existing private `ready` checkpoint, exposed publicly as `needs_details`. Confirmation is blocked until those questions and source requirements are resolved. Existing SQL leases and revision checks remain in use. Older genuinely terminal `needs_details` jobs are not revived; their existing safe fallback asks for a fresh source check.

Raw PDF bytes are never persisted. Private parsed documents are retained as a whole only within a **1,600,000-byte** serialized-text limit and the existing **2,200,000-byte** application checkpoint limit. No silent prefix is kept. Sources beyond this retention limit ask for a smaller assessment overview. Retained page text never enters public status responses; it is cleared on completed proposals and otherwise follows existing owner-only job access/expiry. The browser attachment boundary remains account-session memory; a full browser reload requires reattachment when starting a new read.

The existing three-call and 120-second active budget, stage-specific time allowances, quotas, source ownership/checksums, literal quote checks, explicit version constraints, optional-selection adapter gate, approval ledger and protected saved-profile/generation contexts remain authoritative. A clarification cannot reset the budget or supply a fact in place of evidence. Remaining reference capacity is accounted for before another extraction. New evidence is still validated and merged under existing bounds.

This is a generic deterministic parser, not a promise that every board's PDF layout can be separated. Unsupported or genuinely ambiguous layouts ask a focused source question. No approved preset, source rule pack, paper contract, contract fingerprint or scientific-content authority is added.
